## Context

The project (`qgis/table_mountain_3D.qgz`) is the cartographic source of
truth for what QGIS is good at authoring — the Named Trail Atlas layout, the
3D camera pose, per-layer label placement — but QGIS rewrites the 3D terrain
binding and `texture-size` on every save, and the file is a zip with an
empty aux DB, so diffs are opaque `Bin X -> Y` blobs. This change makes the
project an *enforced* build artifact: the file under git is generated by
`scripts/build_project.py` from curated inputs and machine-checked by
`scripts/verify_project.py`.

## Decision 1 — enforcement build, not full regeneration

A fully regenerated project (YAML spec -> fresh `.qgs`) would require
re-authoring the atlas layout and the 3D camera in code — and the 3D bloom /
colour grading / skybox setters are not exposed to Python in this QGIS 4.2.2
build (`SIP_NO_FILE`; only the `...Changed` signals exist — verified). The
build therefore:

1. loads the current project file,
2. enforces the canonical, machine-checkable state (tree shape, categorized
   trail renderer from `trail_colors.csv`, map themes, project CRS, relative
   paths, basemap sources),
3. stamps the canonical 3D scene XML from a template inside the script, with
   layer ids resolved by layer name at stamp time,
4. re-embeds `qgis/trail_presentation_macro.py` into the `Macros` section,
5. writes `qgis/table_mountain_3D.qgs`.

The atlas layout and the 3D camera remain authored in QGIS and are verified,
not regenerated. This is the honest scope given the unbound 3D API.

## Decision 2 — plain XML storage

The empty aux DB inside the QGZ was verified (0 rows in every table), so
plain `.qgs` storage loses nothing. The committed file becomes
`qgis/table_mountain_3D.qgs`; the `.qgz` is removed from the repo (it is
regenerable by opening and saving, or by zipping the `.qgs` — documented in
README). QGIS opens `.qgs` natively.

## Decision 3 — canonical 3D stamp

The stamp template is the `<qgis3d>` fragment captured from the current
project, parameterised by layer ids:

| placeholder       | resolved from                                 |
|-------------------|-----------------------------------------------|
| `{dem_layer_id}`  | the 5 m DEM layer (terrain source)            |
| `{trail_layer_id}`| the single `Hiking Trails` layer id           |
| tracks/unnamed/...| the remaining scene layers, by name           |
| `{aerial_layer_id}`| the CoCT aerial layer id                      |

Terrain settings pinned by the stamp: `map-theme="3D terrain texture"`,
`texture-size="512"`, `elevation-offset`, `exaggeration`, `shading`, plus the
bloom / colour-grading / eye-dome / shadow blocks. The stamp is idempotent:
running the build twice yields byte-identical XML (checksummed by
`verify_project.py`).

## Decision 4 — verification gate

`scripts/verify_project.py` bootstraps `QgsApplication` offscreen
(`QT_QPA_PLATFORM=offscreen`), loads `qgis/table_mountain_3D.qgs` and asserts:

- project CRS is `EPSG:32734`, paths are relative;
- exactly one named-trail layer (`Hiking Trails`) whose categorized renderer
  has 172 categories and every colour equals `trail_colors.csv`;
- the categorized 3D renderer is present;
- the themes `3D terrain texture`, `Aerial Imagery`, `Trail Inspection`,
  `Single-part trails` exist;
- the 3D XML stamp is present (terrain `map-theme`/`texture-size`, bloom,
  colour grading) — the same check the old regex re-patch performed;
- the atlas coverage is `Hiking Trails` with 172 pages;
- basemap sources: OSM on the MapProxy XYZ endpoint, CoCT aerial on the
  MapProxy WMS endpoint in `EPSG:32734`;
- all layer sources resolve;
- the embedded macro equals `qgis/trail_presentation_macro.py`.

Exit code 0/1 only; each failure prints the failing check.

## Decision 5 — pre-commit wiring

`.pre-commit-config.yaml` gains a local hook `verify-project` (modeled on the
existing `verify-data` hook) using the same system interpreter:
`/usr/bin/python3 scripts/verify_project.py` on `qgis/**` changes and in
`pre-push`. `verify-data` stays the data gate.

## Decision 6 — basemaps

- OSM: MapProxy XYZ (web mercator) — unchanged, attribution retained.
- CoCT aerial: back to the MapProxy **WMS** endpoint, layer `coct_aerial`,
  CRS `EPSG:32734`. The upstream erdas service returns blank imagery in
  `EPSG:3857` and real imagery in `EPSG:32734` (verified 2026-09-29), so
  `coct_aerial_cache` now caches on the `utm34s` grid (crop extent, 10 levels
  from 128 m to 0.25 m/px) and the empty `styles` parameter is forwarded.
  MapProxy WMS GetMap in 32734 returns non-white imagery (verified).

## Repro checks

1. `python3 scripts/build_project.py` twice -> identical sha256.
2. `python3 scripts/verify_project.py` -> exit 0.
3. `pre-commit run --all-files` -> verify-data + verify-project green.
4. Aerial layer renders from WMS in QGIS (screenshot), OSM from XYZ.
5. `git diff` of a subsequent project edit is XML, not a binary blob.

## Non-goals

- Full YAML-spec regeneration of layouts / 3D camera (blocked by unbound 3D
  API; enforcement + verification is the deliverable).
- Publishing the restricted CoCT imagery.
